`/settings` prefix becomes `organization`, as `AGENTS.md` fixes the route shape.

## Endpoints

- `GET /organizations/:org/settings`. `SettingsResolver`, `OrganizationService.settings`. The spec types the response
  as `Domain`. The console types it as `{ identities }`.
- `PATCH /organizations/:org/settings` with `{ identities }`. `OrganizationService.patchSettings`.
- `GET /organizations/:org/identities`. `OrganizationService.identityProviders`.
- `GET /platform/installation`. `InstallationResolver`, `InstallationService.get`.
- `GET /platform/configuration/installation`. `CloudModeService.isCloudModeEnabled`. `type` `managed` is cloud mode.
- `GET /organizations/:org/entrypoints`. `EntrypointsResolver`, `EntrypointService.list`.
- `GET /organizations/:org/entrypoints/:id`. `EntrypointResolver`, `EntrypointService.get`.
- `POST /organizations/:org/entrypoints` with `name`, `description`, `url`, `tags`. `EntrypointService.create`.
- `PUT /organizations/:org/entrypoints/:id` with `name`, `description`, `url`, `tags`. `EntrypointService.update`.
- `DELETE /organizations/:org/entrypoints/:id`. `EntrypointService.delete`.
- `GET /organizations/:org/environments`. `EnvironmentService.getAllEnvironments`, for the environment name of a row.
- `GET /organizations/:org/tags`. `TagsResolver`, `TagService.list`.
- `GET /organizations/:org/tags/:id`. `TagResolver`, `TagService.get`.
- `POST /organizations/:org/tags` with `name`, `description`. `TagService.create`.
- `PUT /organizations/:org/tags/:id` with `name`, `description`. `TagService.update`.
- `DELETE /organizations/:org/tags/:id`. `TagService.delete`.
- `GET /organizations/:org/forms?template=LOGIN`. `FormResolver`, `OrganizationService.forms`.
- `POST /organizations/:org/forms` with the form (`template`, `enabled`, `content`). `OrganizationService.createForm`.
- `PUT /organizations/:org/forms/:id` with `enabled`, `content`. `OrganizationService.updateForm`.
- `DELETE /organizations/:org/forms/:id`. `OrganizationService.deleteForm`.

## Permissions

Organization permissions come from `GET /user`, which `SessionGate` puts in the root permission scope.

- The section needs `organization_settings_read`. The menu entry Organization shows with it.
- `general`: `organization_settings_read`. Save needs `organization_settings_update`.
- `cockpit`: `installation_read`, and not in cloud mode.
- `entrypoints`: `organization_entrypoint_list`. `new` needs `organization_entrypoint_create`, `:id` needs
  `organization_entrypoint_read`. Create button: `organization_entrypoint_create`, hidden in cloud mode. Row edit link:
  `organization_entrypoint_read`, hidden in cloud mode. Row delete and delete zone: `organization_entrypoint_delete`,
  not in cloud mode, not for the default entrypoint. Save: `organization_entrypoint_update`, not in cloud mode.
- `tags`: `organization_tag_list`. `new` needs `organization_tag_create`, `:id` needs `organization_tag_read`. Row
  edit link: `organization_tag_read`. Delete: `organization_tag_delete`. Save: `organization_tag_update`.
- `forms`: `organization_form_list`. `form` needs `organization_form_read`. Create: `organization_form_create`. Save of
  an existing form: `organization_form_update`. Delete: `organization_form_delete`.
- The sidebar shows an item with the permission of its route.

Guards the Angular routes do not have, added because each page loads from an endpoint that needs the permission:
`forms/form` needs `organization_form_read`, which Angular guards on the route as well. The `tags`, `entrypoints` and
`forms` lists carry their own `AuthGuard` and `*_list` permission in Angular, so the console adds none there. The
`cockpit` route in cloud mode leaves for `general`, where the Angular `CloudModeGuard` cancels the navigation.

Cloud mode reads as managed until the installation type loads, so a create, delete or save control shows only once the
type is known. Angular starts from not managed. The organization layout waits for the same call before it sets the
sidebar, because the sidebar reads its groups once.

## Prototype additions left out

- Tag id preview on the creation page, with the create button disabled until a slug exists: not in AM, the backend
  derives the id and Angular only requires a name.
- A `gravitee.yml` example with an explanation of the exclusion prefix: not in AM. The Angular panel shows the two
  comment lines, which the console shows as they are.
- Entrypoints list Sharding tags column: `GET /organizations/:org/entrypoints` does not return `tags`, so the column
  would show no tag for a tagged entrypoint. The Default badge stays, next to the name.
- Tag creation page `gravitee.yml` explanation and "How domains use it" card as cards: Angular shows them as text in the
  side panel. They are cards with the Angular wording.
- Subtitles under the Entrypoints, Forms and Cockpit titles, a Discover or Open Cockpit button, and a Default badge on
  the entrypoint detail title: the Angular pages have none. Kept, as text and links only, with no endpoint behind them.
- Cockpit status badge and installation details card: the data is `id` and `additionalInformation` from the same call.
  Kept.
- Forms list status badge Custom, Custom off, Default: not in AM. Angular lists the template with an edit link and
  greys a template that is not enabled. The console loads no override for the list, as Angular does not.
- Email fields, the email variables and the `emails` kind of `TemplateEditor`: not in AM for the organization.
- The authentication page empty state that points to Identity Providers: kept as a plain note, the Angular page shows
  two empty selects.

## Angular behaviour the prototype dropped

- Cloud mode on entrypoints: no create button, no edit link, no delete, read-only form, no Save.
- Cloud mode on Cockpit: the route is unreachable and the menu hides it.
- The default entrypoint: name, description and tags are read-only, the URL stays editable, and it has no delete.
- Entrypoint creation: the URL must match `https?://.+`.
- The form preview runs in an iframe with an empty `sandbox`, so the custom HTML runs no script. Angular writes the
  document into the iframe, and its scripts run. This is a deliberate difference.
- Entrypoint detail: Angular drops the tag ids that are not in the tag list. The console keeps them and sends them back.
- Form template preview tab, enabled only when the template is enabled and editable.
- Form info dialog with the minimal LOGIN HTML.
- The `Entrypoint` environment column falls back to the environment id.

## Verification

Run on the local stack, Management API on `:8093`, console served on `:4201`, signed in as the seeded admin.

Pages checked: `general`, `tags` (list, new, detail), `entrypoints` (list, new, detail), `forms` (list, editor with the
Html and Preview tabs), `cockpit`. The Angular console on `:4200` was not driven. The calls are compared with the
Angular service code.

| Action                | Call from the console                                       | Angular service                  |
| --------------------- | ----------------------------------------------------------- | -------------------------------- |
| Create a tag          | `POST /organizations/DEFAULT/tags` `{name, description}`    | `TagService.create`              |
| Update a tag          | `PUT .../tags/:id` `{name, description}`                    | `TagService.update`              |
| Delete a tag          | `DELETE .../tags/:id`                                       | `TagService.delete`              |
| Create an entrypoint  | `POST .../entrypoints` `{name, description, url, tags: []}` | `EntrypointService.create`       |
| Update an entrypoint  | `PUT .../entrypoints/:id` `{name, description, url, tags}`  | `EntrypointService.update`       |
| Delete an entrypoint  | `DELETE .../entrypoints/:id`                                | `EntrypointService.delete`       |
| Create the login form | `POST .../forms` `{template: "LOGIN", enabled, content}`    | `OrganizationService.createForm` |
| Delete the login form | `DELETE .../forms/:id`                                      | `OrganizationService.deleteForm` |

Read after the create: the stored form has `template` `login`, as Angular stores it, and the stored entrypoint has the
tag that the update sent.

Not run: the Authentication Save against the live stack, because the stack has one identity provider and a change
there signs the admin out of the console. A unit test covers its payload. The update of an existing form has a unit
test only.

Permission parity: not run. The identity provider of the local stack has no user store, so the stack cannot hold a user
with a given permission set. Unit tests render each guarded route without its permission and assert the `Not allowed`
panel and no API call, and render each action with and without its permission. The menu has a unit test per
permission.

Round trip: the console wrote the tag, entrypoint and form, and the Management API accepted them and returned them to
the console. The Angular side was not opened.

Playwright: `gravitee-am-test/playwright/tests/console-next/organization-settings.spec.ts`, two tests, pass against
the stack.

Defects found and fixed during the verification:

- The sidebar did not show Cockpit after the installation type loaded, because `useSectionSidebar` reads its groups
  once. The layout now waits for the installation type before it sets the sidebar.
- The entrypoints list showed no tag for a tagged entrypoint, because the list endpoint omits `tags`. The column is
  left out.
