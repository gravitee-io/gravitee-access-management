## Endpoints

- `GET .../domains/:domain/applications/search?page&limit&sort=name|updatedAt&dir=asc|desc[&q=*text*]&type=WEB&type=NATIVE&type=BROWSER&type=SERVICE&type=RESOURCE_SERVER`.
  `ApplicationService.search`. The endpoint skips rows by `page`, so the console pages by number without the cursor.
- `GET .../applications/:id`. `ApplicationResolver`, `ApplicationService.get`.
- `GET .../applications/:id/members/permissions`. `ApplicationPermissionsResolver`.
- `POST .../applications` with `name`, `description`, `clientId`, `clientSecret`, `redirectUris`, `type`.
- `POST .../cimd/validate` with `url`. `POST .../cimd/applications` with `name`, `type`, `description`, `cimdUrl`,
  `clientName`.
- `PATCH .../applications/:id`. General, metadata and identity providers each send their own fields.
- `PUT .../applications/:id/type` with `type`. `DELETE .../applications/:id`.
- `GET .../domains/:domain/entrypoints`. `DomainEntrypointResolver`.
- `GET .../applications/:id/analytics?type&field&from&to&interval`. `AnalyticsService.searchApplicationAnalytics`.
- `GET .../domains/:domain/identities` and `GET /platform/plugins/identities?...`. `IdentitiesResolver`.
- `GET /platform/configuration/spel/grammar`. The selection rule editor.
- `GET/POST .../applications/:id/members`, `DELETE .../members/:membershipId`, `GET /organizations/:org/roles?type=APPLICATION`,
  `GET /organizations/:org/users?q=text*&page=0&size=30`, `GET /organizations/:org/groups`. `MembershipsPanel` (AM-7985).

## Permissions

- The list needs `application_list`, `new` needs `application_create`. Angular sets `application_list` on the
  `applications` route as menu data only, so `:appId` does not need it.
- `:appId` loads the application permissions and adds them to the domain ones, then needs `application_read`. Angular
  has no guard here. The guard follows the API, so a deep link shows `Not allowed` in place of an API error, and a
  member of the application alone can still open it.
- `idp` needs `application_identity_provider_list`, `analytics` needs `application_analytics_list`. `general`, `agent`
  and `metadata` need `application_settings_read`, `members` needs `application_member_list`. `settings` itself has no
  guard: Angular sets its permissions as menu data only, and each settings page guards itself.
- The settings index opens the first page the user may open, in the Angular order: general, oauth2, members,
  secrets-certificates, factors. It checks the rules of each page's menu entry, so it never lands on
  `Not allowed`. Angular checks `application_certificate_read` and `application_factor_read` here, which the
  certificates and factors routes do not accept.
- `idp`, `analytics` and `agent` also check the application type, as the Angular route `types` and agent rules do. A deep
  link to a section the type does not have opens `overview`, where Angular opens the console home.
- Each placeholder route checks the rules of its menu entry through `RequireApplicationSection`:
  a missing permission shows `Not allowed`, and a type or a domain SAML switch the section does not have opens
  `overview`.
- The group rules of Design, Settings and Security only hide the group in the menu. Angular sets them on parent routes
  that have no guard, so a deep link to a page checks only the page's own rule.
- The application menu shows each entry with the Angular route permissions, application types, the domain SAML switch
  and the agent rule, through `applicationNavGroups` in `src/app/navigation.ts`.

## Shared parts

`MembershipsPanel` (AM-7985), `SaveBar`, `ConfirmDialog`, `ErrorPanel`, `NotFoundPanel`, `PlaceholderPage`,
`SearchField`. `ActivityChart` and `MetricTile` move from the domain dashboard to `src/app/components/`, because the

## Decisions

- The identity providers page keeps the Angular editor: drag and drop on the rows, move up and move down buttons for the
  keyboard, and a code editor for the selection rule with completion from the expression language grammar.

## Prototype additions left out

- List: the trim of the input values (not in AM, the values are sent as typed).
- Identity providers: the "No user sign-in" state for a service application (not in AM, the menu hides the page) and the
  trim of the selection rule.
- Analytics: the empty state for a service or agent application (not in AM, the menu hides the page).
- Overview: the default-first entrypoint choice (not in AM, the console uses the domain entrypoint rule).
- Agent: the empty state for an application that is not an agent and "Not set" for an empty kind (not in AM).
- Metadata: a removed key sent as `null` (not in AM, the console sends the whole map).

## Angular behaviour added back

- List: the Template status beside Enabled and Disabled, and the server sort by Name or Last updated.
- Create: the full CIMD review with the View metadata JSON dialog and Copy JSON, `clientName` when the document has no
  `client_name`, the client secret dialog with no close button and OK disabled until the copy, the server message in
  the error toasts, the Resource Server type only with UMA on.
- Overview: "Insufficient permission" in place of the client values without `application_openid_read`, the redirect URI
  without its `{#...}` parameters, client-side PKCE values, the token samples by token endpoint auth method, the links
  to identity providers and design, the logout `target_url` note, the copy toast.
- Endpoints: the SCIM, UMA, CIBA and SAML sections by domain setting.
- Identity providers: drag and drop with move buttons, the code editor with grammar completion, the default rule by
  provider type, the rule that selects its provider, the priorities per list from 0.
- Analytics: the 30 and 90 day ranges, default 1 day.
- General: the confirm before a URI removal, the duplicate URI toast, the hidden URI and consent sections for a service
  application, the expression language hint, the CIMD template lock, the type change with its confirm.
- Metadata: the duplicate name error, and values that are not text sent back unchanged until edited.

## Differences

- A new application of type Backend to Backend leaves `redirectUris` out, where Angular sends `null`. The server reads
  both the same.
- A metadata rename to a name that exists shows the error under the field and blocks Save, where Angular shows a toast.
- The main menu shows Applications without a permission check, as it does every domain section. The shell sits above the
  domain permission scope.
- General sends `settings.oauth` only with `application_openid_update`, and shows the URIs and the sign-out toggles
  read-only without it. Angular always sends it, and the server refuses the save without that right. Without
  `application_openid_read` the API leaves `settings.oauth` out, and the page shows "Insufficient permission" in its
  place.
- Identity providers saves only with `application_identity_provider_read` too. Without it the API leaves the links out,
  and an Angular save unlinks every provider.
- An unknown application id shows "Could not load your permissions". The Management API answers 403 for an unknown
  application, to an admin too, so the console cannot tell it from a missing permission.
