`settings/providers/:id` with no segment opens `settings`. A system provider opens `mappers`, because it has no
Settings tab. The role and group pages share `ExpressionMapperPanel.tsx` in the same folder.

## Endpoints

- `GET /organizations/:org/environments/:env/domains/:domain/identities`. `ProvidersResolver`,
  `ProviderService.findByDomain`.
- `POST .../domains/:domain/identities` with `name`, `type`, `configuration`, `external`, `domainWhitelist`.
  `ProviderService.create`.
- `GET .../domains/:domain/identities/:id`. `ProviderResolver`, `ProviderService.get`.
- `PUT .../domains/:domain/identities/:id` with `name`, `type`, `configuration`, `domainWhitelist`, `mappers`,
  `roleMapper`, `groupMapper`. `ProviderService.update`. A system provider has no `configuration`, so the console sends
  `"{}"`, as Angular does.
- `DELETE .../domains/:domain/identities/:id`. `ProviderService.delete`.
- `GET /platform/plugins/identities?expand=icon&expand=displayName&expand=labels` and the same with `external=true`.
  `IdentitiesResolver`, `OrganizationService.identities` and `socialIdentities`.
- `GET /platform/plugins/identities/:type/schema`. `OrganizationService.identitySchema`.
- `GET .../domains/:domain/certificates`. `CertificatesResolver`, `CertificateService.findByDomain`.
- `GET /organizations/:org/environments/:env/data-sources`. `DataSourcesResolver`, `DataSourcesService.findAll`.
- `GET /platform/configuration/installation`. `CloudModeService.isSystemClusterRestricted`. Any error reads as an
  empty configuration.
- `GET .../domains/:domain/entrypoints`. `DomainService.getEntrypoint`.
- `GET .../domains/:domain/roles?page=N&size=50`, every page. `RolesResolver`, `RoleService.findAllByDomain`.
- `GET .../domains/:domain/groups?page=0&size=100`. `GroupsResolver`, `GroupService.findByDomain`.

The list matches `spikeNotes`. The plugin schema form reads its dictionary endpoints through `useAdaptedSchema`.

## Permissions

- The `providers` subtree needs `domain_identity_provider_list`, from the Angular route `perms.only`. The settings
  layout above it needs `domain_settings_read`.
- List: New provider needs `domain_identity_provider_create`. The name link needs `domain_identity_provider_read`. The
  row delete needs `domain_identity_provider_delete`.
- Settings: Save needs `domain_identity_provider_update`. The delete zone needs `domain_identity_provider_delete`.
- User, role and group mappers: add, edit and remove need `domain_identity_provider_update`.

## Licence features

No route feature. The settings Save checks the feature of the provider's plugin, as the Angular `licenseGuard` on
SAVE does. The wizard locks a plugin card whose feature the licence lacks, through `PluginWizard`.

## Shared parts

`PluginWizard`, `PluginSchemaForm` (`useAdaptedSchema`, `pluginSchemaResolver`), `SaveBar`, `ConfirmDialog`,
`TagInput`, `PageHeader`, `ErrorPanel`, `NotFoundPanel`, `UpgradeDialog`.

## Prototype additions left out

- List: the Category column. No endpoint: the plugin catalogue has no category field.
- List: the Last updated column. No endpoint: the identities list has no `updatedAt`.
- List: the hidden delete on a system provider row. Not in AM: Angular shows delete to each user with the permission.
- Wizard: the cards grouped by category. No endpoint.
- The organization scope. Not in this story: AM-7957 ports the organization providers.

## Angular behaviour added back

- List: the type label is the plugin display name, else `Custom`.
- Wizard: the plugin icons, the labels in the filter, and the licence locks.
- Wizard and settings: the certificate, data source and system cluster schema enrichers
  (`provider.form.enricher.ts`, `DataSourcesService.applyDataSourceSelection`).
- Wizard: the domain whitelist pre-filled with `gmail.com` for Google and `microsoft.com` for Azure AD.
- Wizard and settings: the MongoDB user storage guidance.
- Settings: an unset boolean takes its schema default, then no other default applies (AM-686).
- Settings: the pinned MongoDB storage fields go back to the server as stored (`withPinnedStorage`).
- Settings: the confirmation when an inline provider save drops or renames a user.
- Create and update: the BCrypt hash of new inline user passwords (`ProviderService.enhanceConfiguration`).
- Settings: the redirect URI from the domain entrypoint and virtual host, and the custom login snippet.
- Settings: the plugin description, as plain text in the Configuration card. Master Angular shows it in the side
  panel, and at creation since AM-7647. The wizard shows it through `PluginWizard`.
- Settings: the toasts `Provider updated` and `Identity provider deleted`. Create: `Provider <name> created`.
- User mappers: the five default mappers until the provider has its own, and the duplicate toast
  `Error : attribute <key> already exists`.
- Role mappers: the roles from every page. The system primary-owner roles are disabled.
- Role and group mappers: the duplicate message `'<user>' has already the '<name>' role`.

## Kept from the prototype

- User mappers: the rows are edited in place and saved with Save and Discard. Angular saves on each Enter, add and
  delete.
- Group mappers: a remove asks for confirmation, as role mappers do. Angular removes a group entry at once.
- Settings: the redirect URI and the custom login snippet sit in an Integration card, in place of the Angular side
  panel.
- Settings and mappers: the inputs are disabled for a reader. Angular leaves them editable and hides only Save.

## Not ported

- The HTML of the plugin description. Angular renders it with `innerHTML`. Of the 15 identity provider schemas, only
  LinkedIn holds a tag, an anchor without `href`.
- The EL grammar autocompletion of `gv-expression-language`. The expression fields are plain text inputs.

## Decisions

- `bcryptjs` 3.0.3 added to the console, with approval, for the BCrypt hash of inline user passwords.
- The list has a client-side search and client-side pages, with approval. Angular and the prototype show neither.
- The generated `Role` model does not compile, because it references an undeclared `InnerEnum`. `src/lib/api/roles.ts`
  types the three role fields it reads by hand.
- `GET /platform/plugins/identities/:type/schema` answers 204 for a plugin that has no schema, for example an
  enterprise plugin without its licence. The console reads that as a schema without fields, as Angular renders no
  configuration form.
- A field that the stored configuration lacks registers as an `undefined` key, and the Graphene switch of an unset
  boolean writes `false`. React Hook Form counted both as a change, so the settings form opened with the save banner.
  `withAbsentFields` in `provider-schema.ts` puts the same values in the defaults. The PUT body does not change.
- Save of a settings form sits in the layout banner, outside a `LicenseGuard`. The settings submit opens the upgrade
  dialog when the licence lacks the plugin feature.

### Parity with the Angular console

The Angular console `4.10.x-latest` ran on `:4200` beside the React console, against the same API, on a throwaway
domain `idp-parity` with a Google, an inline and the system provider, a role mapper and a group mapper. A script read
the headings, buttons, tabs, fields, text and API calls of seven pages on both consoles: the list, the Google and
inline settings, the Google user, role and group mappers, and the system provider. The master Angular commits after
4.10 that touch `settings/providers` were then read one by one.

| Page            | Result                                                                                                          |
| --------------- | --------------------------------------------------------------------------------------------------------------- |
| List            | Same rows, type labels and `System` origin. Same two plugin calls                                               |
| Google settings | Same fields, whitelist, redirect URI and login snippet. The plugin description was missing: added               |
| Inline settings | Same user fields, password encoder and delete                                                                   |
| Both settings   | The React form opened with the save banner when the stored configuration lacked a field: fixed                  |
| User mappers    | Same rows. Angular also calls `GET /platform/configuration/spel/grammar` for the EL autocompletion (not ported) |
| Role, group     | Same mappings, same `roles?page=0&size=50` and `groups?page=0&size=100` calls                                   |
| System provider | Same three tabs, no Settings tab. Angular 4.10 logs a `JSON.parse` error on this page; React does not           |

Master commits after 4.10: AM-7647 (the plugin description at creation and on settings) is added, see above.
AM-7612 (the system cluster lock and disclaimer) and the pinned storage of #8429 are in `provider-schema.ts`.
"lock unlicensed features" is in `PluginWizard` and the settings Save. The rest are a typo rename and spacing.

Differences from Angular:

- The schema form sends `encodeRedirectUri: false` and `scopes: []` on a Google create, where the user leaves them.
  This comes from the shared `PluginSchemaForm` of AM-7984. The plugin reads the same values as its defaults.
- The API returns `mappers: {}` for a new provider, so no default user mappers show. Angular does the same, because an
  empty object is truthy.

Playwright: `gravitee-am-test/playwright/tests/console-next/identity-providers.spec.ts` has three tests: the system
provider opens on User mappers with no Settings tab, a user mapper saves (the test waits for the PUT response), and
the list deletes a provider. They did not run on this stack. The `testDomain` fixture waits for the gateway sync on
`:18092`, which the `dev` stack does not publish. The master spec `domain-settings-webauthn.spec.ts` fails the same
way on this stack.
