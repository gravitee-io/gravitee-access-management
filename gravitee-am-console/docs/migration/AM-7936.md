# AM-7936 Migrate the domain settings forms to React

The story ships in two stacked pull requests. Part 1 holds the settings layout, General and Entrypoints. Part 2 holds
Login, Web protection, User accounts and WebAuthn.

## Part 1

### Pages

| Angular route          | Prototype page          | Console file                                         |
| ---------------------- | ----------------------- | ---------------------------------------------------- |
| `settings` (layout)    | `DomainSettingsLayout`  | `src/features/settings/DomainSettingsLayout.tsx`     |
| `settings/general`     | `DomainGeneralPage`     | `src/features/settings/DomainGeneralPage.tsx`        |
| `settings/entrypoints` | `DomainEntrypointsPage` | `src/features/entrypoints/DomainEntrypointsPage.tsx` |

`settings` with no segment opens `settings/general`. The other settings menu items keep a placeholder until their story
mounts them.

### Endpoints

- `PATCH /organizations/:org/environments/:env/domains/:domain` with `name`, `description`, `path`, `enabled`, `tags`,
  `oidc { postLogoutRedirectUris, requestUris }`, `master`. `DomainService.patchGeneralSettings`.
- `DELETE /organizations/:org/environments/:env/domains/:domain`. `DomainService.delete`.
- `GET /organizations/:org/tags`. `TagsResolver`, `TagService.list`.
- `GET /organizations/:org/environments/:env/data-planes`. `DataPlanesResolver`.
- `GET /organizations/:org/environments/:env/domains/:domain/entrypoints`. `DomainEntrypointResolver`,
  `DomainService.getEntrypoint`.
- `PATCH /organizations/:org/environments/:env/domains/:domain` with `path`, `vhostMode`, `vhosts`.
  `DomainService.patchEntrypoints`.
- `GET /platform/configuration/installation`. `CloudModeService`. Any error reads as no cloud mode, as in Angular.

The environment `domainRestrictions` come from the session environment list, as `EnvironmentResolver` reads them.

### Permissions

- The layout, General and Entrypoints routes need `domain_settings_read`.
- General: the URI add and remove controls, the form inputs and Save need `domain_settings_update`. The delete zone
  needs `domain_settings_delete`.
- Entrypoints: the inputs, the override radio, the add and remove virtual host buttons and Save need
  `domain_settings_update`. Cloud mode makes the page read-only.
- The settings menu shows an item only when the user has one of the permissions of its Angular route, as
  `AuthGuard.canDisplay` does.

### Licence features

None.

### Shared parts

`SaveBar`, `ConfirmDialog`, `ValueListInput`, `SettingToggle`, `PageHeader`, `ErrorPanel`, `useSectionSidebar`.

### Prototype additions left out

- General: the trim of the name on save. Not in AM.
- Entrypoints: the path pattern rule and the "cannot be '/'" rule in context-path mode. Not in AM, Angular only
  requires the path.
- Entrypoints: the switch mode button gated on the update permission. Not in AM, Angular shows it to every reader
  outside cloud mode.
- Entrypoints: the resolved URL under each virtual host. Not in AM.
- The menu keys that differ from the Angular segments: `trusted-domains`, `device-identifiers`, `services`,
  `extension-grants`, `client-registration`. The console uses the Angular segments `trust-domains`,
  `device-identifier`, `resources`, `extensionGrants`, `dcr`.

### Angular behaviour added back

- General: the domain path in the payload, sent unchanged.
- General: after a save that changes the hrid, the page moves to the new `settings/general` URL.
- General: the duplicate toasts `Error : redirect URI "<uri>" already exists` and
  `Error : request URI "<uri>" already exists`.
- General: the remove confirmations `Remove logout redirect URI` and `Remove request URI`, and the delete confirmation
  `Delete Domain`, with the Angular texts. The toasts `Domain <name> updated` and `Domain <name> deleted`.
- General: the data plane field, shown only when the environment has more than one data plane.
- Entrypoints: cloud mode hides the switch mode button, the add and remove buttons and Save.
- Entrypoints: the host pattern built from the environment `domainRestrictions`, and the host suggestions of
  `getHostOptions`.
- Entrypoints: the entrypoint choice of `DomainService.getEntrypoint`: the only one, else the first non-default one,
  else the first one.

### Kept from the prototype

- General: delete lands on the domains list, where Angular opens the console root.
- General and Entrypoints: the inputs are disabled for a reader. Angular General leaves them editable and hides only
  Save.
- Entrypoints: the access URL card, computed as `EntrypointService.resolveBaseUrl` does, in place of the Angular side
  panel.

### Verification

2026-10-30, React console on `:4201` against the local Management API (the `authz-e2e` stack, standalone
installation), on a throwaway domain `settings-port-check`, deleted after. The Angular console was not running (`:4200`
is the Gamma console), so the calls were compared with `DomainService`.

- `settings` opened `settings/general`. The sidebar showed the settings menu.
- General save: `PATCH /organizations/DEFAULT/environments/DEFAULT/domains/:id`
  `{name, description, path (unchanged), enabled, tags, oidc {postLogoutRedirectUris, requestUris}, master}`, the seven
  fields of `patchGeneralSettings`. Toast `Domain settings-port-check updated`.
- A duplicate URI showed `Error : redirect URI "https://app.example/two" already exists`. A removal opened
  `Remove logout redirect URI` / `Are you sure you want to remove this redirect URI ?`.
- Rename to `settings port check2`: the same PATCH, then the page moved to `.../settings-port-check2/settings/general`.
- Entrypoints load: `GET .../domains/:id/entrypoints` and `GET /platform/configuration/installation`. The entrypoint URL
  was `http://localhost:8092`.
- Context-path save: PATCH `{path: "/spc", vhostMode: false, vhosts: []}`. The access URL card showed
  `http://localhost:8092/spc`.
- Virtual hosts: the host `bad host` showed `Enter a host, with an optional port.` and disabled Save. Then
  `auth.spc.example:8092` saved PATCH `{path: "/spc", vhostMode: true, vhosts: [{host, path: "/spc",
overrideEntrypoint: true}]}`. The access URL card showed `http://auth.spc.example:8092/spc`.
- Delete: `Delete Domain` / `Are you sure you want to delete this domain ?`, then
  `DELETE /organizations/DEFAULT/environments/DEFAULT/domains/:id`, the toast `Domain settings port check2 deleted`,
  and the domains list.
- Enter in the Name input saves while the form has changes, as the Angular form does with its SAVE submit button.

Not checked in the browser: a reader without `domain_settings_update`, cloud mode, and the domain restrictions host
suggestions. The unit tests cover them.

## Part 2

### Pages

| Angular route             | Prototype page            | Console file                                              |
| ------------------------- | ------------------------- | --------------------------------------------------------- |
| `settings/login`          | `DomainLoginPage`         | `src/features/login/DomainLoginPage.tsx`                  |
| `settings/web-protection` | `DomainWebProtectionPage` | `src/features/web-protection/DomainWebProtectionPage.tsx` |
| `settings/account`        | `UserAccountsPage`        | `src/features/account/DomainAccountPage.tsx`              |
| `settings/webauthn`       | `WebAuthnPage`            | `src/features/webauthn/DomainWebAuthnPage.tsx`            |

### Endpoints

- `PATCH /organizations/:org/environments/:env/domains/:domain` with `loginSettings`. `DomainService.patchLoginSettings`.
- `PATCH /organizations/:org/environments/:env/domains/:domain` with `corsSettings` and `webProtectionSettings`.
  `DomainService.patchWebProtectionSettings`.
- `PATCH /organizations/:org/environments/:env/domains/:domain` with `accountSettings`.
  `DomainService.patchAccountSettings`.
- `GET /organizations/:org/environments/:env/domains/:domain/identities?userProvider=true`.
  `ProviderService.findUserProvidersByDomain`.
- `GET /organizations/:org/environments/:env/domains/:domain/bot-detections`. `BotDetectionService.findByDomain`.
- `GET /organizations/:org/environments/:env/domains/:domain/entrypoints`. `DomainEntrypointResolver`.
- `PATCH /organizations/:org/environments/:env/domains/:domain` with `webAuthnSettings`.
  `DomainService.patchWebAuthnSettings`. The Management API replaces the whole object.

### Permissions

- The four routes need `domain_settings_read`.
- Login, Web protection and WebAuthn: the inputs, the add and remove actions and Save need `domain_settings_update`.
- User accounts: the form is editable with `domain_settings_create` or `domain_settings_update`.

### Licence features

None.

### Shared parts

`SaveBar`, `SettingToggle`, `TagInput`, `DurationInput`, `PageHeader`, `ErrorPanel`. `DurationInput` gets an optional
`describedBy` prop, so a duration error is linked to its input. `accessUrl` moves to `src/lib/api/domains.ts`, because
Entrypoints and WebAuthn both use it.

### Prototype additions left out

- Login: every `LoginSettings` field defaulted and sent. Not in AM.
- Web protection: value lists for Allow-Origin and Allow-Headers, which use `TagInput` as Angular uses chips; the raw
  HTML directive name list, which is a Graphene Combobox over the Angular directive names; the trim of a directive
  name. Not in AM.
- User accounts: the custom form fields, confirm identity and the bot plugin sent as null when off; the durations saved
  with their defaults when the feature was never on; the trim of a new field label; an unknown stored provider id added
  to the select; "None" sent as null. Not in AM.
- WebAuthn: a removed certificate and an unspecified select sent as null; the trim of a new certificate value; the
  entrypoint picked default first. Not in AM.

### Angular behaviour added back

- Login: the payload keeps the stored fields the form does not show, with `inherited: false`. The max passwordless
  usage is checked only while password usage is enforced.
- Web protection: the defaults of `initializeSettings`; a stored max age of 0 shown empty and an empty one sent as 0;
  the duplicate toasts `Error : Origin "<value>" already exists` and `Error : Header "<value>" already exists`; the max
  age min 0 rule; `csp-directives.ts` with its spec.
- User accounts: the stored settings spread into the payload; the defaults on enable (10 attempts, 12 hours, 2 hours, 14
  days, 3 MFA attempts, 1 minute); the toast `User Accounts Settings updated`.
- WebAuthn: the origin and RP ID defaults from the access URL; the inline edit of a certificate, as an Edit action, with
  `Error : attestation "<name>" already exists`; `Error : metadata "<name>" already exists` on add; the max age min 0
  rule.

### Kept from the prototype

- The inputs are disabled for a reader, as in part 1.
- The menu titles and page titles come from the prototype, for example "Web Protection" where Angular says "Web
  protection". The route keys are the Angular segments.
- User accounts: a stored duration shows in the largest exact unit; each failing rule shows its own message; the custom
  form check does not skip the MFA and remember me checks, which Angular skips once the custom form is on; the MFA
  switch is named MFA brute force detection.
- Web protection: a typed origin or header is added when the field loses focus. Angular adds it on Save. A typed value alone
  does not make the form dirty, so the Save bar shows after the field loses focus or after Enter.

### Verification

2026-10-30, React console on `:4201` against the local Management API, on a throwaway domain `settings-port-check-2`,
deleted after. The calls were compared with `DomainService` and the spike payloads in `units.json`.

- Login: User registration, passwordless, enforce password usage and a max age of 3600. PATCH
  `{loginSettings: {registerEnabled, passwordlessEnabled, passwordlessEnforcePasswordEnabled,
passwordlessEnforcePasswordMaxAge: 3600, inherited: false}}`, 200, toast `Login configuration updated`.
- Web protection: a duplicate origin showed `Error : Origin "https://app.example" already exists`. A second
  `default-src` showed `This directive is already configured`, linked to its input, and disabled Save. PATCH
  `{corsSettings {inherited false, allowedOrigins, allowedMethods [GET], allowedHeaders [], allowCredentials false,
enabled true, maxAge 600}, webProtectionSettings {csp {inherited false, enabled true, reportOnly false,
scriptInlineNonce true, directives}, xframe {inherited true, enabled false, action DENY}, xss {inherited true,
enabled false, action "1; mode=block"}}}`, 200, toast `Web protection settings for settings-port-check-2 updated`.
- User accounts: brute force on showed 10 attempts, 12 and 2. Blocked duration 30 Minutes. The custom form with no
  field disabled Save, then Email. PATCH `{accountSettings {loginAttemptsDetectionEnabled true, maxLoginAttempts 10,
resetPasswordCustomForm true, inherited false, loginAttemptsResetTime 43200, accountBlockedDuration 1800,
mfaChallengeAttemptsResetTime 0, rememberMeDuration 0, resetPasswordCustomFormFields [email]}}`, 200, toast
  `User Accounts Settings updated`. A reload showed 30 Minutes and the Email field.
- WebAuthn: the origin defaulted to `http://localhost:8092` and the RP ID to `localhost`. A second `packed` showed
  `Error : metadata "packed" already exists`. PATCH `{webAuthnSettings {origin, relyingPartyId, forceRegistration true,
userVerification required, certificates {packed}}}`, 200. A reload showed the saved values.
- Web protection, on a second throwaway domain `wp-blur-check`, deleted after: with the form already changed, a typed
  origin followed by a click on Save sent the origin in `allowedOrigins`. On an unchanged form, the Save bar showed
  after the origin field lost focus, and the save sent the origin.

Not checked in the browser: a reader, the WebAuthn inline edit, and the bot detection select. The unit tests cover them.
