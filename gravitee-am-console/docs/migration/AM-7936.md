# AM-7936 Migrate the domain settings forms to React

The story ships in two stacked pull requests. Part 1 holds the settings layout, General and Entrypoints. Part 2 holds
Login, Web protection, User accounts and WebAuthn.

## Part 1

### Pages

| Angular route          | Prototype page          | Console file                                         |
| ---------------------- | ----------------------- | ---------------------------------------------------- |
| `settings` (layout)    | `DomainSettingsLayout`  | `src/features/settings/DomainSettingsLayout.tsx`     |
| `settings/general`     | `DomainGeneralPage`     | `src/features/settings/DomainGeneralPage.tsx`        |
| `settings/entrypoints` | `DomainEntrypointsPage` | `src/features/entrypoints/DomainEntrypointsPage.tsx` |

`settings` with no segment opens `settings/general`. The other settings menu items keep a placeholder until their story
mounts them.

### Endpoints

- `PATCH /organizations/:org/environments/:env/domains/:domain` with `name`, `description`, `path`, `enabled`, `tags`,
  `oidc { postLogoutRedirectUris, requestUris }`, `master`. `DomainService.patchGeneralSettings`.
- `DELETE /organizations/:org/environments/:env/domains/:domain`. `DomainService.delete`.
- `GET /organizations/:org/tags`. `TagsResolver`, `TagService.list`.
- `GET /organizations/:org/environments/:env/data-planes`. `DataPlanesResolver`.
- `GET /organizations/:org/environments/:env/domains/:domain/entrypoints`. `DomainEntrypointResolver`,
  `DomainService.getEntrypoint`.
- `PATCH /organizations/:org/environments/:env/domains/:domain` with `path`, `vhostMode`, `vhosts`.
  `DomainService.patchEntrypoints`.
- `GET /platform/configuration/installation`. `CloudModeService`. Any error reads as no cloud mode, as in Angular.

The environment `domainRestrictions` come from the session environment list, as `EnvironmentResolver` reads them.

### Permissions

- The layout, General and Entrypoints routes need `domain_settings_read`.
- General: the URI add and remove controls, the form inputs and Save need `domain_settings_update`. The delete zone
  needs `domain_settings_delete`.
- Entrypoints: the inputs, the override radio, the add and remove virtual host buttons and Save need
  `domain_settings_update`. Cloud mode makes the page read-only.
- The settings menu shows an item only when the user has one of the permissions of its Angular route, as
  `AuthGuard.canDisplay` does.

### Licence features

None.

### Shared parts

`SaveBar`, `ConfirmDialog`, `ValueListInput`, `SettingToggle`, `PageHeader`, `ErrorPanel`, `useSectionSidebar`.

### Prototype additions left out

- General: the trim of the name on save. Not in AM.
- Entrypoints: the path pattern rule and the "cannot be '/'" rule in context-path mode. Not in AM, Angular only
  requires the path.
- Entrypoints: the switch mode button gated on the update permission. Not in AM, Angular shows it to every reader
  outside cloud mode.
- Entrypoints: the resolved URL under each virtual host. Not in AM.
- The menu keys that differ from the Angular segments: `trusted-domains`, `device-identifiers`, `services`,
  `extension-grants`, `client-registration`. The console uses the Angular segments `trust-domains`,
  `device-identifier`, `resources`, `extensionGrants`, `dcr`.

### Angular behaviour added back

- General: the domain path in the payload, sent unchanged.
- General: after a save that changes the hrid, the page moves to the new `settings/general` URL.
- General: the duplicate toasts `Error : redirect URI "<uri>" already exists` and
  `Error : request URI "<uri>" already exists`.
- General: the remove confirmations `Remove logout redirect URI` and `Remove request URI`, and the delete confirmation
  `Delete Domain`, with the Angular texts. The toasts `Domain <name> updated` and `Domain <name> deleted`.
- General: the data plane field, shown only when the environment has more than one data plane.
- Entrypoints: cloud mode hides the switch mode button, the add and remove buttons and Save.
- Entrypoints: the host pattern built from the environment `domainRestrictions`, and the host suggestions of
  `getHostOptions`.
- Entrypoints: the entrypoint choice of `DomainService.getEntrypoint`: the only one, else the first non-default one,
  else the first one.

### Kept from the prototype

- General: delete lands on the domains list, where Angular opens the console root.
- General and Entrypoints: the inputs are disabled for a reader. Angular General leaves them editable and hides only
  Save.
- Entrypoints: the access URL card, computed as `EntrypointService.resolveBaseUrl` does, in place of the Angular side
  panel.

### Verification

2026-10-30, React console on `:4201` against the local Management API (the `authz-e2e` stack, standalone
installation), on a throwaway domain `settings-port-check`, deleted after. The Angular console was not running (`:4200`
is the Gamma console), so the calls were compared with `DomainService`.

- `settings` opened `settings/general`. The sidebar showed the settings menu.
- General save: `PATCH /organizations/DEFAULT/environments/DEFAULT/domains/:id`
  `{name, description, path (unchanged), enabled, tags, oidc {postLogoutRedirectUris, requestUris}, master}`, the seven
  fields of `patchGeneralSettings`. Toast `Domain settings-port-check updated`.
- A duplicate URI showed `Error : redirect URI "https://app.example/two" already exists`. A removal opened
  `Remove logout redirect URI` / `Are you sure you want to remove this redirect URI ?`.
- Rename to `settings port check2`: the same PATCH, then the page moved to `.../settings-port-check2/settings/general`.
- Entrypoints load: `GET .../domains/:id/entrypoints` and `GET /platform/configuration/installation`. The entrypoint URL
  was `http://localhost:8092`.
- Context-path save: PATCH `{path: "/spc", vhostMode: false, vhosts: []}`. The access URL card showed
  `http://localhost:8092/spc`.
- Virtual hosts: the host `bad host` showed `Enter a host, with an optional port.` and disabled Save. Then
  `auth.spc.example:8092` saved PATCH `{path: "/spc", vhostMode: true, vhosts: [{host, path: "/spc",
overrideEntrypoint: true}]}`. The access URL card showed `http://auth.spc.example:8092/spc`.
- Delete: `Delete Domain` / `Are you sure you want to delete this domain ?`, then
  `DELETE /organizations/DEFAULT/environments/DEFAULT/domains/:id`, the toast `Domain settings port check2 deleted`,
  and the domains list.
- Enter in the Name input saves while the form has changes, as the Angular form does with its SAVE submit button.

Not checked in the browser: a reader without `domain_settings_update`, cloud mode, and the domain restrictions host
suggestions. The unit tests cover them.
