## Endpoints

`...` is `/organizations/:org/environments/:env/domains/:domain`.

- `GET .../users?page=N&size=S`. `UserService.findByDomain`.
- `GET .../users?q=<text>*&page=N&size=S`, or `?filter=<SCIM filter>&page=N&size=S` when the text holds a SCIM
  operator. `UserService.search`. The Management API reads `q` before `filter`, so the console never sends both.
- `POST .../users` with `firstName`, `lastName`, `email`, `username`, `password`, `client`, `source`,
  `forceResetPassword`, `preRegistration`, and `additionalInformation` when the user added an attribute.
  `UserService.create`.
- `GET .../users/:id`. `UserResolver`, `UserService.get`.
- `PUT .../users/:id` with `firstName`, `lastName`, `displayName`, `email`, `enabled`, `client`,
  `additionalInformation`, `forceResetPassword`. `UserService.update`.
- `PATCH .../users/:id/username` with `username`. `UserService.updateUsername`.
- `PUT .../users/:id/status` with `enabled`. `UserService.updateStatus`.
- `POST .../users/:id/resetPassword` with `password`. `UserService.resetPassword`.
- `POST .../users/:id/unlock`. `UserService.unlock`.
- `POST .../users/:id/sendRegistrationConfirmation`. `UserService.resendRegistrationConfirmation`.
- `DELETE .../users/:id`. `UserService.delete`.
- `GET .../users/:id/audits?page=N&size=10&from=T&to=T[&type=X][&status=SUCCESS|FAILURE]`. `UserService.audits`.
- `GET .../identities` and `GET .../identities?userProvider=true`. `ProviderService.findByDomain` (list filter) and
  `findUserProvidersByDomain` (create form). Already in `src/lib/api/identity-providers.ts`.
- `GET .../applications?page=0&size=50` (list filter) and `GET .../applications?q=<text>*` (application picker).
  `ApplicationService.findByDomain` and `search`. New file `src/lib/api/applications.ts`, which AM-7948 extends.
- `GET .../password-policies/activePolicy[?identity=<idp id>]`. `PasswordPolicyService.getPolicyForIdp`. A 404 reads
  as no policy, as `SKIP_404_REDIRECT` does.
- `POST .../password-policies/:policyId/evaluate` with `userId`, `password`. `PasswordPolicyService.evaluatePassword`,
  called by the password policy check when the policy excludes dictionary words or keeps a password history.
- `GET /platform/configuration/users/email-required`. `UserService.isEmailRequired`.
- `GET /platform/audits/events`. `OrganizationService.auditEventTypes`.

`spikeNotes` lists no calls for this unit: the spike did not port it. The list above comes from the Angular services.

## Permissions

- The `users` subtree needs `domain_user_list`, from the Angular route `perms.only`. The settings layout above it
  needs `domain_settings_read`.
- `new` needs `domain_user_create`. `:userId` and its tabs need `domain_user_read`. Both as in Angular.
- The settings menu shows Users with `domain_user_list` (already in `navigation.ts`).
- List: Create user needs `domain_user_create`. The name links to the user with `domain_user_read`, else it is text.
- Profile: the fields are editable, and Save, Update username, the application picker, Force password reset and
  Add attribute show, with `domain_user_update`.
- Layout actions: Reset password, Unlock, Send confirmation and Enable or Disable need `domain_user_update`. Delete
  needs `domain_user_delete`.
- History: the event details open with `domain_audit_read`, as the Angular expand column.

## Angular behaviour added back

- List: the advanced filters (identity provider, application, disabled) build the Angular SCIM filter, joined with
  `or` inside a filter and `and` between filters. A filter replaces the text search and a text search clears the
  filters, as the Angular advanced search writes its filter in the search field.
- List: the text search sends `q=<text>*`, or `filter=<text>` with a SCIM operator.
- List: the Identity provider and Last login columns show with `domain_user_read` only, as the Angular columns.
- Create: the email is required only when `email-required` says so.
- Create: the password policy check of the identity provider under the password. Create stays disabled until the
  password passes, unless pre-registration is on.
- Create and profile: the application picker searches the applications by name or client id.
- Create: `additionalInformation` is sent only when the user added an attribute.
- Profile: the first name shows when it is set or the user is internal, the last name when it is set. Each is
  required when shown. The email shows when it is set or the user is internal.
- Profile: an existing attribute keeps its name and edits its value. An object value is read-only. A null value is
  kept as stored.
- Profile: Force password reset shows for an internal user.
- Profile: the username cannot start or end with whitespace. An update asks for confirmation and unlocks the account.
- Reset password: the password policy check under the new password.
- History: a start and end date range, with the quick time range when it is unset. Default range Today, 10 rows.
  The range ends at the end of its last day, where Angular ends it at midnight, so a range of one day is not empty.
- Toasts: `User <username> created`, `User updated`, `Username updated`, `User enabled`, `User disabled`,
  `User unlocked`, `Email sent`, `Password reset`, `User <username> deleted`.

## Changes from Angular

- The order follows the prototype where it groups fields in cards. The create form puts Force password reset in the
  Credentials card, under the password, where Angular puts it in its own section after Identity provider. The account
  actions are in the header menu (Reset password, Unlock, Send confirmation, Enable or Disable, Delete), where Angular
  lists them at the foot of the profile. The list shows the username and status in their own columns, where Angular
  shows them in the Name cell. The User Type column is not shown: Angular shows it in the organization scope only.
- The advanced filters put a criterion with several values in parentheses. Angular joins them bare, and the SCIM
  parser binds `and` before `or`, so two applications with a second filter read as `a1 or (a2 and ...)`.
- A profile save sends an unedited boolean or number attribute back with its type. Every row holds its value as
  text, so without this `email_verified: true` would go back as `"true"`.
- The labels, help text and confirmations follow the prototype. The Angular hints that only restate the label, such
  as "The first name of the User.", are dropped. The create page sits in `PageFocused`.
- After each write the console reads the user again. A `PUT` or `PATCH` answers with the stored user, without the
  application and identity provider names that `GET` adds, so the activity card would show the raw ids.
- `src/monaco-setup.ts` gives Monaco its editor and JSON workers. This story is the first to use `CodeEditor`. Without
  the workers Monaco logs "Unexpected usage" when the audit details open.

### Permission parity

Each test role is a domain role with `domain_read` and `domain_settings_read`. Angular also guards the settings
parent with `domain_settings_read`.

| Role adds                              | Menu Users   | List                             | `new`                            | Profile, History                 | Create, user link                 | Edit, Actions                                |
| -------------------------------------- | ------------ | -------------------------------- | -------------------------------- | -------------------------------- | --------------------------------- | -------------------------------------------- |
| Nothing                                | React hidden | React `Not allowed`, Angular `/` | Both refused                     | Both refused                     | Not reached                       | Not reached                                  |
| `domain_user_list`                     | Both shown   | Both show the rows               | React `Not allowed`, Angular `/` | React `Not allowed`, Angular `/` | Both hidden                       | Not reached                                  |
| `domain_user_list`, `domain_user_read` | Both shown   | Both show the rows               | Not checked                      | Both open                        | Link shown, Create hidden on both | Both read-only, no Actions, no audit details |

No guard shows an API error panel in place of `Not allowed`.

### Round trip

`rt-ng` created in Angular opens in React with its stored values and no save banner. `rt-react` created in React,
with the same input, opens in Angular with its stored values. The two MongoDB documents differ only in `_id`,
`externalId`, `username` and `email`.

During the run the local stack lost all its domains and organization users, which another process caused. The Delete
and Send confirmation checks ran again on the new domain `am7943-qa`.
